# Scan Conversion & Polygon Filling Algorithms

## 1. Explanation

Polygon scan conversion (also called **polygon rasterization** or **polygon filling**) is the process of identifying every interior pixel of a polygon and writing a fill color into those pixel locations in the frame buffer.

This is fundamentally different from wireframe rendering (which only draws the boundary edges). Filled polygon rendering is the backbone of all solid 3D graphics: every visible triangle face in a 3D game, every filled shape in a 2D graphic, is generated by a scan-conversion algorithm.

---

### Inside-Outside Tests

Before filling, we must reliably determine whether an arbitrary point $P(x, y)$ lies **inside** or **outside** a polygon. Two standard topological rules exist:

#### 1. Even-Odd (Parity) Rule

**Algorithm**:
1. Cast a ray from $P(x, y)$ in any fixed direction (typically $+x$, toward $x = \infty$).
2. Count the number of polygon boundary edges the ray crosses.
3. **Odd count → Inside; Even count → Outside.**

**Intuition**: Each time the ray crosses a boundary, you toggle between inside and outside. Starting outside the polygon (at $x = \infty$), an odd number of crossings means you end up inside.

**Vertex handling rule**: If the ray passes exactly through a vertex:
- Count it as 1 intersection if the two adjoining edges are on **opposite sides** of the ray (one above, one below).
- Count it as 0 (or 2) intersections if both adjoining edges are on the **same side** of the ray (local extremum — both above or both below).

**Limitation**: Fails to correctly classify interior regions of **self-intersecting polygons** (e.g., the central region of a 5-pointed star is classified as "outside" by even-odd, which may not match artistic intent).

#### 2. Non-Zero Winding Number Rule

**Algorithm**:
1. Cast a ray from $P$ to $+\infty$.
2. Initialize winding number $W = 0$.
3. For each polygon edge that **crosses the ray**:
   - If the edge crosses from **bottom to top** (upward crossing): $W = W + 1$
   - If the edge crosses from **top to bottom** (downward crossing): $W = W - 1$
4. **$W \ne 0$ → Inside; $W = 0$ → Outside.**

**Intuition**: The winding number counts how many times the polygon boundary "winds around" the query point. If it winds at least once (net), the point is considered inside.

**Key difference from even-odd**: For self-intersecting polygons, the winding rule fills the central region (since wound-around areas have $W=2$), while the even-odd rule leaves it as a hole. Font rendering (TrueType, PostScript) typically uses the non-zero winding rule.

### Polygon Filling Algorithms

#### 1. Scan-Line Fill Algorithm (Preferred for Large Polygons)

The scan-line algorithm is the **industrial-standard** method for filling arbitrarily shaped polygons in real-time graphics. It works by sweeping horizontal scanlines from the bottom of the polygon to the top, computing edge intersections and filling horizontal spans.

##### Why Scanline Is Efficient

**Spatial coherence**: Adjacent scanlines share most of their edge intersection data — only small incremental updates are needed from one scanline to the next. This avoids recomputing intersections from scratch.

##### Key Data Structures

**Edge Table (ET)**:
- Stores all non-horizontal polygon edges, organized by their lowest $y$-coordinate ($y_{\min}$).
- Each edge entry stores: $\{y_{\max},\ x_{\text{current}},\ \Delta x = \frac{1}{m} = \frac{x_2 - x_1}{y_2 - y_1}\}$
- Horizontal edges are **excluded** (they lie on a single scanline and don't generate crossings).
- Within each $y_{\min}$ bucket, edges are sorted by increasing $x$ value.

**Active Edge Table (AET)**:
- Dynamic list of edges that intersect the current scanline $y$.
- Maintained in sorted order of current $x$-coordinate.
- Updated incrementally each scanline.

##### Step-by-Step Algorithm

```
Build Edge Table (ET):
  For each polygon edge (V_i, V_{i+1}):
    If NOT horizontal (y_1 ≠ y_2):
      ymin = min(y_i, y_{i+1})
      ymax = max(y_i, y_{i+1})
      x_at_ymin = x coordinate at the lower vertex
      delta_x = (x_{upper} - x_{lower}) / (y_upper - y_lower)  // = 1/m
      Insert record {ymax, x_at_ymin, delta_x} into ET[ymin] bucket

Initialize AET = empty
Set y = minimum y_value in ET

Loop while (AET not empty OR ET not empty):
  1. MERGE: Move all edges from ET[y] into AET
  2. REMOVE: Delete edges from AET where y_max == y
  3. SORT: Sort AET by current x value
  4. FILL: For pairs (x1, x2), (x3, x4), ... in sorted AET:
           Fill pixels: x = ceil(x1) to floor(x2) at scanline y
  5. INCREMENT: y = y + 1
  6. UPDATE: For each edge in AET: x_current = x_current + delta_x

Stop.
```

##### Vertex Parity Rule (Critical!)

When a scanline passes through a vertex shared by two edges:
- **Local minimum or maximum** (both edges on same side): Count vertex as **2 intersections** (enters and exits) — net effect: adds 0 or 2 to parity, doesn't toggle inside/outside.
- **Monotone vertex** (edges on opposite sides): Count vertex as **1 intersection** — toggles inside/outside.

Practical rule: When an edge's $y_{\min}$ equals the scanline $y$, include it; when an edge's $y_{\max}$ equals $y$, exclude it (don't add to AET). This ensures vertices are counted correctly.

#### 2. Boundary Fill Algorithm

Boundary fill starts at an interior **seed point** and recursively spreads outward, stopping at a predefined **boundary color**.

**Use case**: Interactive paint programs where the user clicks inside a region to fill it, and the region boundary is already drawn in a specific color.

##### 4-Connected Boundary Fill (Recursive)

```c
void BoundaryFill4(int x, int y, int fillColor, int boundaryColor) {
    int cur = GetPixel(x, y);
    if (cur != boundaryColor && cur != fillColor) {
        SetPixel(x, y, fillColor);
        BoundaryFill4(x+1, y,   fillColor, boundaryColor); // East
        BoundaryFill4(x-1, y,   fillColor, boundaryColor); // West
        BoundaryFill4(x,   y+1, fillColor, boundaryColor); // North
        BoundaryFill4(x,   y-1, fillColor, boundaryColor); // South
    }
}
```

##### 8-Connected Boundary Fill (Recursive)

```c
void BoundaryFill8(int x, int y, int fillColor, int boundaryColor) {
    int cur = GetPixel(x, y);
    if (cur != boundaryColor && cur != fillColor) {
        SetPixel(x, y, fillColor);
        BoundaryFill8(x+1, y,   fillColor, boundaryColor);
        BoundaryFill8(x-1, y,   fillColor, boundaryColor);
        BoundaryFill8(x,   y+1, fillColor, boundaryColor);
        BoundaryFill8(x,   y-1, fillColor, boundaryColor);
        BoundaryFill8(x+1, y+1, fillColor, boundaryColor); // NE
        BoundaryFill8(x-1, y+1, fillColor, boundaryColor); // NW
        BoundaryFill8(x+1, y-1, fillColor, boundaryColor); // SE
        BoundaryFill8(x-1, y-1, fillColor, boundaryColor); // SW
    }
}
```

**4-connected vs 8-connected**:
- **4-connected** stops at diagonal boundaries (pixels only share edges, not corners). Appropriate for regions with single-pixel boundary lines.
- **8-connected** crosses diagonal boundaries (pixels share corners). Fills regions connected diagonally, but may leak through thin diagonal boundaries (1 pixel wide diagonal "lines" don't form barriers in 8-connected).

**Practical problem**: Deep recursion causes stack overflow for large regions. For a $1920\times1080$ image, the worst-case stack depth is $\sim 2$ million frames. **Solution**: Replace recursion with an explicit stack (queue), or use a scanline-based iterative variant.

---

#### 3. Flood Fill Algorithm

Flood fill replaces all connected pixels of the **same old color** as the seed pixel with a **new fill color**. Unlike boundary fill, there's no explicit boundary color — the fill spreads to all pixels matching the original interior color.

```c
void FloodFill4(int x, int y, int newColor, int oldColor) {
    if (newColor == oldColor) return; // prevent infinite loop
    if (GetPixel(x, y) == oldColor) {
        SetPixel(x, y, newColor);
        FloodFill4(x+1, y,   newColor, oldColor);
        FloodFill4(x-1, y,   newColor, oldColor);
        FloodFill4(x,   y+1, newColor, oldColor);
        FloodFill4(x,   y-1, newColor, oldColor);
    }
}
```

**8-connected flood fill** (also exists):
Adds 4 diagonal neighbors to the recursive calls.

**Flood fill vs Boundary fill**:
| Aspect | Boundary Fill | Flood Fill |
|---|---|---|
| **Stopping criterion** | Specific boundary color pixel | No matching oldColor pixel |
| **Input** | Seed + boundary color + fill color | Seed + old color + new color |
| **Use case** | Outlined region fill | Region defined by uniform interior color |
| **Requires pre-drawn outline** | Yes | No |

## 2. Example: Scan-Line Fill Trace

**Polygon**: Triangle with vertices $A(2, 2)$, $B(10, 2)$, $C(6, 8)$.

**Edge Table construction**:
- Edge $AB$: $y_1 = y_2 = 2$ → **horizontal, skip**
- Edge $BC$: $(10,2) \to (6,8)$. $y_{\min}=2, y_{\max}=8, x_{\text{at}\,y_{\min}}=10, \Delta x = \frac{6-10}{8-2} = \frac{-4}{6} = -\frac{2}{3}$
- Edge $CA$: $(6,8) \to (2,2)$. $y_{\min}=2, y_{\max}=8, x_{\text{at}\,y_{\min}}=2, \Delta x = \frac{6-2}{8-2} = \frac{4}{6} = \frac{2}{3}$

**ET**: Bucket $y=2$: Edge $CA \{8, x=2, +2/3\}$, Edge $BC \{8, x=10, -2/3\}$

| Scanline $y$ | AET entries $(x, \Delta x)$ | Fill span ($x_1$ to $x_2$) |
|---|---|---|
| $y=2$ | $(2, +2/3), (10, -2/3)$ | 2 to 10 |
| $y=3$ | $(2.67, +2/3), (9.33, -2/3)$ | 3 to 9 |
| $y=4$ | $(3.33, +2/3), (8.67, -2/3)$ | 4 to 8 |
| $y=5$ | $(4.00, +2/3), (8.00, -2/3)$ | 4 to 8 |
| $y=6$ | $(4.67, +2/3), (7.33, -2/3)$ | 5 to 7 |
| $y=7$ | $(5.33, +2/3), (6.67, -2/3)$ | 6 to 6 |
| $y=8$ | Both edges reach $y_{\max}$; remove from AET | — |

## 3. Applications & Use Cases

1. **GPU Triangle Rasterization**: Modern GPU hardware implements a highly parallel scanline fill to rasterize triangles. Each GPU core processes one or more "tiles" (8×8 or 16×16 pixel blocks) simultaneously. The triangle is set up by computing edge equations, then each tile tests all its pixels against the edge half-spaces — a vectorized generalization of the scanline approach.

2. **Font Rendering (FreeType, DirectWrite)**: TrueType glyphs are defined as closed quadratic Bézier contours. The font engine flattens these contours into polygon edges, then applies scanline fill with the non-zero winding rule to rasterize characters at any point size. This is what makes text appear crisp on screens.

3. **Paint Bucket Tool (Photoshop, Krita, GIMP)**: The interactive "fill bucket" tool executes an optimized flood fill. Modern implementations use **scanline flood fill** (iterative, pushing entire scanline spans rather than individual pixels) to avoid stack overflow and improve cache performance.

4. **GIS / Cartography**: Geographic Information Systems like QGIS and ArcGIS fill political boundaries, water bodies, parks, and land parcels by scan-converting polygon geometries that may have thousands of vertices. The scanline ET/AET approach handles arbitrary concave polygons and polygon-with-holes (using multiple polygon contours and winding rules).

5. **Vector Graphics Rendering (SVG, PDF)**: PDF and SVG renderers use scanline polygon fill for all filled shapes. The PostScript/PDF standard specifies the non-zero winding rule and even-odd rule as explicit fill modes for paths.

### Example 1: Scan-Line Fill — Full ET/AET Trace [KTU Jan 2023 — 9 Marks]

**Problem**: Given a polygon with vertices $A(1,1)$, $B(7,1)$, $C(9,5)$, $D(5,7)$, $E(1,5)$. Apply the scan-line polygon fill algorithm. Build the Edge Table and show AET for scanlines $y=2$, $y=3$, $y=4$.

**Step 1 — Build Edge Table:**

| Edge | From → To | Horizontal? | $y_{\min}$ | $y_{\max}$ | $x$ at $y_{\min}$ | $\Delta x = 1/m$ |
|---|---|---|---|---|---|---|
| AB | (1,1)→(7,1) | Yes | — | — | — | — (excluded) |
| BC | (7,1)→(9,5) | No | 1 | 5 | 7 | $(9-7)/(5-1) = 2/4 = 0.5$ |
| CD | (9,5)→(5,7) | No | 5 | 7 | 9 | $(5-9)/(7-5) = -4/2 = -2$ |
| DE | (5,7)→(1,5) | No | 5 | 7 | 5 | $(1-5)/(5-7) = -4/-2 = 2$ |
| EA | (1,5)→(1,1) | No | 1 | 5 | 1 | $(1-1)/(1-5) = 0$ |

**ET Buckets:**
- $y=1$: Edge $EA\{5, x=1, \Delta x=0\}$, Edge $BC\{5, x=7, \Delta x=0.5\}$
- $y=5$: Edge $CD\{7, x=9, \Delta x=-2\}$, Edge $DE\{7, x=5, \Delta x=2\}$

**Step 2 — Trace:**

**Scanline $y=2$**:
- Merge $ET[2]$: none. AET = {$EA(x=1+0=1)$, $BC(x=7+0.5=7.5)$}
- Wait — at $y=2$, edges that entered at $y_{\min}=1$ have been updated once: $x_{EA} = 1+0=1$, $x_{BC} = 7+0.5=7.5$
- Fill: $x=1$ to $x=7$ (pixels at $x = 1,2,3,4,5,6,7$)

**Scanline $y=3$**:
- Update: $x_{EA} = 1+0 = 1$, $x_{BC} = 7.5+0.5 = 8$
- Fill: $x=1$ to $x=8$

**Scanline $y=4$**:
- Update: $x_{EA} = 1$, $x_{BC} = 8+0.5 = 8.5$
- Fill: $x=1$ to $x=8$

### Example 2: Non-Zero Winding Number Rule Computation [KTU Dec 2021, Dec 2022 — 4 Marks]

**Problem**: Consider a simple polygon with vertices $A(2,0)$, $B(10,0)$, $C(10,8)$, $D(2,8)$ (a rectangle). Using the non-zero winding rule, determine if point $P(5,4)$ is inside or outside. Edges are ordered counter-clockwise.

**Solution**:

Edges (CCW order): $A\to B \to C \to D \to A$

Cast a ray from $P(5,4)$ in $+x$ direction (toward $x = \infty$).

| Edge | Direction | Crosses ray at $x > 5$, $y = 4$? | Winding contribution |
|---|---|---|---|
| $A(2,0) \to B(10,0)$ | Rightward, $y=0$ | No (ray at $y=4$, edge at $y=0$) | 0 |
| $B(10,0) \to C(10,8)$ | Upward, $x=10$ | Yes! (edge goes up, crosses $y=4$ at $x=10>5$) | $+1$ (upward crossing) |
| $C(10,8) \to D(2,8)$ | Leftward, $y=8$ | No (ray at $y=4$, edge at $y=8$) | 0 |
| $D(2,8) \to A(2,0)$ | Downward, $x=2$ | No ($x=2 < 5$; ray goes $+x$) | 0 |

$W = +1 \ne 0$ → **Point $P(5,4)$ is INSIDE the polygon.** ✓

### Example 3: Boundary Fill vs. Flood Fill — 4-Connected on Grid [KTU May 2019 — 4 Marks]

**Problem**: On the following 5×5 pixel grid, pixel $(2,2)$ is the seed. Boundary color = **B** (black). Fill color = **G** (gray). Trace 4-connected boundary fill.

```
Grid (y increases upward):
Row 4: . B . . .
Row 3: . B B . .
Row 2: . B . . .   ← seed = (2,2) which is '.' interior
Row 1: . B B B .
Row 0: . . . . .

Where B = boundary (black), . = interior (white/empty)
```

**4-Connected Boundary Fill starting at seed $(2,2)$**:

The algorithm checks $\{(3,2),(1,2),(2,3),(2,1)\}$ from seed $(2,2)$:
- $(3,2)$ = white → fill it, recurse: check $(4,2),(2,2),(3,3),(3,1)$
- $(1,2)$ = **B** → stop this branch
- $(2,3)$ = **B** → stop this branch
- $(2,1)$ = **B** → stop this branch

Continuing recursion from $(3,2)$:
- $(4,2)$ = white → fill, recurse...
- $(3,3)$ = white → fill, recurse...
- $(3,1)$ = **B** → stop

The fill propagates through all interior white pixels reachable by 4-connected paths from $(2,2)$ without crossing any **B** pixel.

**Key observation**: 8-connected fill would additionally check diagonal neighbors like $(3,3)$ directly from $(2,2)$, allowing it to reach regions that may be diagonally adjacent but not orthogonally adjacent to the seed region.

### Q1 [KTU June 2024 — 4 Marks]
**Question**: Write the flood fill algorithm to fill a polygon.

**Solution**:

The **Flood Fill Algorithm** fills a connected region by replacing all pixels of a target old color with a new fill color, starting from a seed pixel.

**4-Connected Recursive Flood Fill:**
```
Input: seed coordinates (x, y), newColor, oldColor
Output: All pixels of oldColor connected to (x, y) are changed to newColor

Algorithm FloodFill4(x, y, newColor, oldColor):
  1. If (x, y) is outside display bounds: return
  2. currentColor = GetPixel(x, y)
  3. If currentColor == oldColor:
       SetPixel(x, y, newColor)         // color this pixel
       FloodFill4(x+1, y, newColor, oldColor)  // go East
       FloodFill4(x-1, y, newColor, oldColor)  // go West
       FloodFill4(x, y+1, newColor, oldColor)  // go North
       FloodFill4(x, y-1, newColor, oldColor)  // go South
  4. Else: return (pixel is not oldColor — either boundary or already filled)
```

**8-Connected variant** additionally checks the 4 diagonal neighbors $(x\pm1, y\pm1)$ in Step 3.

**Important**: If `newColor == oldColor`, the algorithm will run infinitely (every pixel already matches). Always check and return early in this case.

### Q2 [KTU Jan 2023 — 9 Marks]
**Question**: Write the scan line algorithm for filling a polygon.

**Solution**:

**Scan-Line Polygon Fill Algorithm:**

**Prerequisite Data Structures:**
- **Edge Table (ET)**: Array indexed by $y$-scanline, containing all non-horizontal polygon edges sorted by $y_{\min}$. Each entry: $(y_{\max}, x_{\text{current}}, \Delta x = (x_2 - x_1)/(y_2 - y_1))$
- **Active Edge Table (AET)**: Working list of edges currently crossing the active scanline, sorted by $x_{\text{current}}$.

**Algorithm:**
```
Step 1: Build Edge Table (ET)
  For each polygon edge (P_i, P_{i+1}):
    Skip if y_i == y_{i+1} (horizontal edge)
    Insert into ET[y_min(P_i, P_{i+1})]:
      record = {y_max, x_at_ymin, delta_x = (x_max - x_min)/(y_max - y_min)}

Step 2: Initialize
  AET = empty list
  y = minimum y in ET

Step 3: Loop until ET and AET both empty:
  a. Move all edges from ET[y] into AET
  b. Remove from AET all edges where y_max == y
  c. Sort AET by x_current (ascending)
  d. Fill pixel spans: for each pair (x1, x2) in AET:
       for x = round(x1) to round(x2): SetPixel(x, y, fillColor)
  e. y = y + 1
  f. For each edge in AET: x_current = x_current + delta_x

Step 4: Stop
```

**Vertex Rule**: When an edge's $y_{\min}$ equals the current scanline, include it. When $y_{\max}$ equals the scanline, remove it. This ensures vertices shared between two edges are counted consistently (once for a local min/max, twice for a crossing vertex).

### Q3 [KTU Dec 2021 — 4 Marks]
**Question**: For what purpose do we use the non-zero winding number rule? How is it used? Illustrate with an example.

**Solution**:

**Purpose**: The non-zero winding number rule determines whether a point lies inside a polygon, especially for **self-intersecting polygons** or polygons with holes. Unlike the even-odd rule, it correctly fills complex shapes like a 5-pointed star's center region.

**Algorithm**:
1. From the query point $P$, cast a ray in any fixed direction (say, $+x$).
2. Initialize winding counter $W = 0$.
3. For each polygon edge that crosses the ray:
   - If the edge crosses from **below to above** (upward): $W += 1$
   - If the edge crosses from **above to below** (downward): $W -= 1$
4. If $W \ne 0$: point is **inside**. If $W = 0$: point is **outside**.

**Example**: Consider a 5-pointed star polygon drawn CCW. Point at the center:
- The star boundary winds **twice** around the center.
- Winding number at center $W = 2 \ne 0$ → **Inside** (the center gets filled).

Under the even-odd rule, the ray from the center crosses 4 edges (even) → classified as **outside** (the center would appear as a hole — a "star cutout" effect).

**Practical application**: SVG and PDF graphics use the fill-rule attribute to choose between `evenodd` and `nonzero` winding, giving designers control over how self-intersecting paths are filled.

### Q4 [KTU Dec 2020 / Sep 2020 — 4 Marks]
**Question**: Compare Boundary fill and Flood fill algorithm.

**Solution**:

| Feature | Boundary Fill | Flood Fill |
|---|---|---|
| **Trigger condition** | Stops at a specified **boundary color** | Stops when pixel color ≠ **old interior color** |
| **Input** | Seed point + fill color + boundary color | Seed point + old color + new color |
| **Region definition** | Defined by its **outline** (boundary drawn first) | Defined by **interior** (uniform old color) |
| **Boundary required** | Yes — outline must be pre-drawn in boundary color | No — entire region has same old color |
| **Multiple boundary colors** | Difficult — boundary must be a single uniform color | Works naturally — stops at any non-oldColor pixel |
| **Self-contained** | Can leak if boundary has gaps (even 1-pixel gap) | No leak risk (stops at any color different from oldColor) |
| **Typical use case** | Line-art coloring (cartoon fill) | Replacing a uniformly colored region |

**Both share common limitation**: Recursive implementation risks **stack overflow** for large regions. Solution: use an **iterative implementation with an explicit queue/stack** storing (x, y) coordinates of pending pixels.

### Q5 [KTU May 2019, Dec 2019 — 4 Marks]
**Question**: Explain the boundary fill algorithm using 4-connected approach.

**Solution**:

**Boundary Fill — 4-Connected Approach**:

The 4-connected boundary fill algorithm fills a polygon interior starting from a seed pixel, spreading only to the **four orthogonal neighbors** (North, South, East, West) — not diagonals.

**Algorithm**:
```
Procedure BoundaryFill4(x, y, fillColor, boundaryColor):
  Input: Seed pixel (x, y), color to fill with, color of boundary

  current = GetPixel(x, y)
  
  If (current ≠ boundaryColor) AND (current ≠ fillColor):
    SetPixel(x, y, fillColor)         // paint this pixel
    BoundaryFill4(x+1, y, fillColor, boundaryColor)  // East neighbor
    BoundaryFill4(x-1, y, fillColor, boundaryColor)  // West neighbor
    BoundaryFill4(x, y+1, fillColor, boundaryColor)  // North neighbor
    BoundaryFill4(x, y-1, fillColor, boundaryColor)  // South neighbor
```

**Working**:
- The algorithm paints a pixel and then recursively attempts to paint its 4 neighbors.
- Recursion terminates at any pixel that is already the fill color (already painted) or the boundary color (the polygon outline).
- The fill "grows" from the seed outward in all directions simultaneously (depth-first).

**Example trace**: Seed at center of a 3×3 square (filled with white, boundary with black):
- Paint center → check E, W, N, S
- Each white neighbor gets painted → check their neighbors
- When a neighbor is black (boundary), that branch stops
- Final result: all white interior pixels are filled

**Limitation**: For a large region of $N$ pixels, this requires up to $N$ recursive call frames on the program stack, potentially causing stack overflow. For production code, replace with an iterative implementation using a LIFO stack or FIFO queue.
