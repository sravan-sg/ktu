# Authentication Protocols and Digital Signatures

## 1. Explanation
A **Digital Signature** is an asymmetric cryptographic mechanism that binds an entity to a digital message or document. It is the electronic analogue of a handwritten signature, but offers far stronger mathematical guarantees.

### Essential Properties of Digital Signatures
According to William Stallings (*Cryptography and Network Security*, Chapter 13), a digital signature scheme must satisfy four core security properties:
1. **Authenticity**: Verifies that the signature was generated by the legitimate signer holding the private key.
2. **Integrity**: Verifies that the document was not altered after signing.
3. **Non-repudiation**: The signer cannot falsely deny having signed the document; any third party or arbiter can verify the signature using the signer's public key.
4. **Unforgeability**: It is computationally infeasible for anyone lacking the signer's private key to forge a valid signature for any message.

```
                  Digital Signature Scheme
       Signer (Private Key PR_A)            Verifier (Public Key PU_A)
              Message M                           Message M
                  │                                   │
                  ▼                                   ▼
          [ Hash Function H ]                 [ Hash Function H ]
                  │                                   │
                  ▼ Digest h                          ▼ Digest h'
       [ Sign with PR_A ]                             │
                  │                                   ▼
                  ▼ Signature s               [ Verify with PU_A, s ]
           Transmit (M, s) ───────────────────► Match h == h'?
```

### The Digital Signature Standard (DSS) and DSA
The **Digital Signature Standard (DSS)** was published by NIST as FIPS PUB 186 in 1991. DSS specifies the **Digital Signature Algorithm (DSA)**, which is based on the discrete logarithm problem (similar to ElGamal and Schnorr signature schemes).

#### DSA Parameters & Key Generation
1. **Global Public Parameters** (shared among a group of users):
   - A prime number $p$ where $2^{L-1} < p < 2^L$ for $L \in \{1024, 2048, 3072\}$.
   - A prime divisor $q$ of $(p - 1)$ where $2^{N-1} < q < 2^N$ for $N \in \{160, 224, 256\}$.
   - A generator $g$ computed as:
     $$g = h^{(p - 1)/q} \bmod p$$
     for some integer $1 < h < (p - 1)$ such that $g > 1$.
2. **User Private Key**:
   - Select a random integer $x$ such that:
     $$1 \le x \le q - 1$$
3. **User Public Key**:
   - Compute public value $y$:
     $$y = g^x \bmod p$$
   - Public Key: $\{p, q, g, y\}$, Private Key: $\{x\}$.

#### DSA Signature Generation
To sign a message $M$:
1. Generate a random per-message secret integer $k$ such that $1 < k < q$. ($k$ must be cryptographically random and never reused!).
2. Compute signature component $r$:
   $$r = (g^k \bmod p) \bmod q$$
   If $r = 0$, pick a new random $k$.
3. Compute signature component $s$:
   $$s = k^{-1} \cdot (H(M) + x \cdot r) \bmod q$$
   where $k^{-1}$ is the modular multiplicative inverse of $k \bmod q$, and $H(M)$ is the hash of the message (using SHA-1 or SHA-256).
   If $s = 0$, pick a new random $k$.
4. The digital signature is the pair:
   $$\text{Signature} = (r, s)$$

#### DSA Signature Verification
Given received message $M'$ and signature $(r', s')$:
1. Verify that $0 < r' < q$ and $0 < s' < q$. If not, reject.
2. Compute:
   $$w = (s')^{-1} \bmod q$$
   $$u_1 = (H(M') \cdot w) \bmod q$$
   $$u_2 = (r' \cdot w) \bmod q$$
3. Compute verification test value $v$:
   $$v = \Big((g^{u_1} \cdot y^{u_2}) \bmod p\Big) \bmod q$$
4. **Signature Test**: If $v == r'$, the signature is verified as authentic. Otherwise, it is rejected.

#### Mathematical Proof of Correctness
We show that $v = r$:
Recall: $s = k^{-1}(H(M) + xr) \bmod q \implies k \equiv s^{-1}(H(M) + xr) \equiv w H(M) + w x r \equiv u_1 + u_2 x \pmod q$.
Since $g$ has order $q$ modulo $p$ ($g^q \equiv 1 \pmod p$):
$$g^k \equiv g^{u_1 + u_2 x} \equiv g^{u_1} \cdot (g^x)^{u_2} \equiv g^{u_1} \cdot y^{u_2} \pmod p$$
Taking modulo $q$:
$$r = (g^k \bmod p) \bmod q = \Big((g^{u_1} \cdot y^{u_2}) \bmod p\Big) \bmod q = v$$
Q.E.D.

### Authentication Protocols
Authentication protocols ensure mutual verification of identities before exchanging sensitive session data.
- **Mutual Authentication**: Both parties authenticate each other, preventing masquerading.
- **Replay Attack Defense**: Employs nonces (numbers used once), timestamps, or challenge-response handshakes.
- **Kerberos**: A trusted third-party authentication service based on symmetric encryption (the Needham-Schroeder protocol), utilizing an Authentication Server (AS) and a Ticket Granting Server (TGS).

## 2. Example: DSA Signature Verification Flow
```
        Signing Process                             Verification Process
    Message M ──► [ SHA-1 ] ──► H(M)             Message M' ──► [ SHA-1 ] ──► H(M')
                     │                                             │
                     ▼                                             ▼
  k ──► [ r = (g^k mod p) mod q ]                                  w = s'^-1 mod q
  │                  │                                             u_1 = H(M')w mod q
  ▼                  ▼                                             u_2 = r'w mod q
[ s = k^-1(H(M)+xr) mod q ]                                        v = (g^u1 · y^u2 mod p) mod q
         │           │                                             │
         ▼           ▼                                             ▼
       ( r     ,     s ) ────────────────────────────────► Compare v == r'?
```

## 3. Applications & Use Cases
1. **Code Signing & App Store Verification**: Apple and Google sign mobile application bundles using digital signatures (ECDSA/RSA) to ensure application integrity before allowing installation on iOS/Android devices.
2. **SSH Public Key Authentication**: Secure Shell (SSH) authenticates remote system administrators by having the client sign a challenge nonce with their private SSH key.

## 4. Solved Numerical / Analytical Examples

### Example 1: Full DSA Numerical Signing and Verification [KTU Analytical Model]
**Problem**:
Given DSA parameters: $q = 11$, $p = 23$ (since $11 \mid (23 - 1)$), $g = 2$, private key $x = 8$.
Public key $y = g^x \bmod p = 2^8 \bmod 23 = 256 \bmod 23 = 3$.
Sign a message with hash $H(M) = 4$ using per-message secret $k = 9$. Then verify the signature.

**Step-by-step Solution**:
1. **Signature Generation**:
   - Calculate $r$:
     $$r = (g^k \bmod p) \bmod q = (2^9 \bmod 23) \bmod 11$$
     $2^9 = 512 = 22 \times 23 + 6 \implies 2^9 \bmod 23 = 6$.
     $$r = 6 \bmod 11 = \mathbf{6}$$
   - Calculate $k^{-1} \bmod q = 9^{-1} \bmod 11$:
     $9 \times 5 = 45 = 4 \times 11 + 1 \implies k^{-1} = 5$.
   - Calculate $s$:
     $$s = k^{-1}(H(M) + x \cdot r) \bmod q$$
     $$s = 5 \times (4 + 8 \times 6) \bmod 11 = 5 \times (4 + 48) \bmod 11 = 5 \times 52 \bmod 11$$
     Since $52 \equiv 8 \pmod{11}$:
     $$s = (5 \times 8) \bmod 11 = 40 \bmod 11 = \mathbf{7}$$
   - **Signature**: $(r, s) = (6, 7)$.

2. **Signature Verification**:
   - Given $(r', s') = (6, 7)$ and $H(M') = 4$:
   - Calculate $w = (s')^{-1} \bmod q = 7^{-1} \bmod 11$:
     $7 \times 8 = 56 = 5 \times 11 + 1 \implies w = 8$.
   - Calculate $u_1 = (H(M') \cdot w) \bmod q$:
     $$u_1 = (4 \times 8) \bmod 11 = 32 \bmod 11 = \mathbf{10}$$
   - Calculate $u_2 = (r' \cdot w) \bmod q$:
     $$u_2 = (6 \times 8) \bmod 11 = 48 \bmod 11 = \mathbf{4}$$
   - Compute test value $v$:
     $$v = \Big((g^{u_1} \cdot y^{u_2}) \bmod p\Big) \bmod q = \Big((2^{10} \cdot 3^4) \bmod 23\Big) \bmod 11$$
     - $2^{10} = 1024 = 44 \times 23 + 12 \equiv 12 \pmod{23}$.
     - $3^4 = 81 = 3 \times 23 + 12 \equiv 12 \pmod{23}$.
     - Product: $(12 \times 12) \bmod 23 = 144 = 6 \times 23 + 6 \equiv 6 \pmod{23}$.
     - Taking modulo $q = 11$:
       $$v = 6 \bmod 11 = \mathbf{6}$$
   - Verification test: $v == r'$ ($6 == 6$). **Signature is valid!**

### Example 2: The Catastrophic Effect of Reusing $k$ in DSA
**Problem**:
Show how an attacker can recover the signer's private key $x$ if the same secret $k$ is used to sign two distinct messages $M_1$ and $M_2$.

**Step-by-step Solution**:
1. Suppose signatures $(r, s_1)$ and $(r, s_2)$ are generated using the identical $k$ ($r$ is identical because $r = (g^k \bmod p) \bmod q$).
2. Signatures:
   $$s_1 = k^{-1}(H(M_1) + xr) \bmod q$$
   $$s_2 = k^{-1}(H(M_2) + xr) \bmod q$$
3. Subtract $s_2$ from $s_1$:
   $$s_1 - s_2 = k^{-1}(H(M_1) - H(M_2)) \pmod q$$
4. The private key $x$ cancels out! The attacker computes $k$ directly:
   $$k = \frac{H(M_1) - H(M_2)}{s_1 - s_2} \bmod q$$
5. Once $k$ is known, the private key $x$ is immediately recovered:
   $$x = \frac{s_1 \cdot k - H(M_1)}{r} \bmod q$$
   (This exact flaw compromised the Sony PlayStation 3 ECDSA signature verification in 2010).

### Example 3: Replay Attack on Mutual Authentication
**Problem**:
Explain how a simple challenge-response mutual authentication protocol without timestamps or session nonces is vulnerable to a reflection replay attack.

**Step-by-step Solution**:
- Suppose Alice authenticates to Bob:
  1. Alice $\rightarrow$ Bob: "I am Alice".
  2. Bob $\rightarrow$ Alice: Challenge $R_1$.
  3. Alice $\rightarrow$ Bob: $E_K(R_1)$. Bob verifies.
- Reflection attack:
  - Darth impersonates Alice and sends: "I am Alice".
  - Bob sends challenge $R_1$.
  - Darth cannot compute $E_K(R_1)$. Instead, Darth opens a *second concurrent connection* to Bob purporting to be Bob: "I am Bob".
  - Bob sends a new challenge $R_2$ to Darth.
  - Darth sends $R_1$ to Bob on connection 2. Bob encrypts $R_1$ with $K$ and returns $E_K(R_1)$ to Darth!
  - Darth takes $E_K(R_1)$ and responds to Bob on connection 1, successfully authenticating as Alice without knowing $K$!

### Question 1 [KTU May 2019, Part C, Q16(b) / January 2023, Part C, Q16 - 9 Marks]
**Question**: Discuss Digital Signature Algorithm (DSA). With figure describe the signing and verifying process in DSS.

**Solution**:
1. **Overview & DSS Context**:
   The Digital Signature Algorithm (DSA) is the core algorithm of the Digital Signature Standard (DSS) established by NIST (FIPS PUB 186). Unlike RSA, which can be used for both encryption and signing, DSA is dedicated **exclusively to digital signatures**. Its security is anchored in the computational intractability of the Discrete Logarithm Problem.

2. **DSS Architectural Diagram**:
```
  [ SIGNING PROCESS ]                              [ VERIFICATION PROCESS ]
  Message M                                       Received Message M'
      │                                                   │
      ▼                                                   ▼
 [ SHA Hash ] ──► H(M)                               [ SHA Hash ] ──► H(M')
      │                                                   │
      │   k (Random per-message secret)                   │
      ▼   │                                               ▼
 [ Compute r = (g^k mod p) mod q ]                        w = (s')^-1 mod q
      │                                                   u_1 = (H(M') · w) mod q
      ▼                                                   u_2 = (r' · w) mod q
 [ Compute s = k^-1(H(M) + xr) mod q ]                    v = ((g^u1 · y^u2) mod p) mod q
      │                                                   │
      ▼                                                   ▼
Signature (r, s) ─────────────────────────────────► Is v == r'?
                                                    (YES = Valid, NO = Rejected)
```

3. **Global Parameters & Keys**:
   - $p$: A prime modulus ($1024$ to $3072$ bits).
   - $q$: A prime divisor of $p - 1$ ($160$ to $256$ bits).
   - $g$: A generator of order $q$ modulo $p$, defined as $g = h^{(p-1)/q} \bmod p$.
   - **Private Key**: $x$ randomly selected from $\{1, 2, \dots, q-1\}$.
   - **Public Key**: $y = g^x \bmod p$.

4. **Signing Process**:
   To sign message $M$:
   1. Choose a random secret integer $k$ with $0 < k < q$.
   2. Compute $r = (g^k \bmod p) \bmod q$.
   3. Compute $s = k^{-1} \cdot (H(M) + x \cdot r) \bmod q$.
   4. The signature is the pair $(r, s)$.

5. **Verification Process**:
   To verify received signature $(r', s')$ on message $M'$ using public key $y$:
   1. Check that $0 < r' < q$ and $0 < s' < q$.
   2. Compute $w = (s')^{-1} \bmod q$.
   3. Compute $u_1 = (H(M') \cdot w) \bmod q$ and $u_2 = (r' \cdot w) \bmod q$.
   4. Compute $v = \Big((g^{u_1} \cdot y^{u_2}) \bmod p\Big) \bmod q$.
   5. If $v == r'$, the signature is verified as valid.

### Question 2 [KTU May 2019 / June 2022 - 4 Marks]
**Question**: Differentiate between direct digital signatures and arbitrated digital signatures.

**Solution**:

| Comparison Attribute | Direct Digital Signature | Arbitrated Digital Signature |
|---|---|---|
| **Involvement of Third Party** | Involves only the sender (signer) and the receiver. No intermediate party is required. | Involves a trusted third party called an **Arbiter**, who validates the message before forwarding. |
| **Verification Method** | Receiver verifies the signature directly using the sender's public key $PU_A$. | The sender sends message and signature to the Arbiter. The Arbiter validates it and sends an arbitrated token to the receiver. |
| **Vulnerability to Private Key Theft** | If an attacker steals sender's private key $PR_A$, they can sign forged messages. The sender cannot easily prove key compromise retroactively. | The Arbiter logs timestamps and checks revocation status in real time, preventing exploitation of revoked keys. |
| **Message Confidentiality** | Sender can encrypt the signed message with receiver's public key for confidentiality. | Can be configured so the Arbiter cannot read plaintext (by signing message digests). |
| **Complexity & Overhead** | Low network overhead; point-to-point transmission. | Higher latency and operational complexity due to dependency on Arbiter availability. |
