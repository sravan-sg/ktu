# Andrew File System (AFS)

## Explanation
The **Andrew File System (AFS)**, developed at Carnegie Mellon University, is a distributed file system designed for scale. Unlike NFS, which is geared towards local area networks and relies heavily on frequent client-server interactions, AFS was designed to support thousands of workstations over wide area networks with a strong focus on caching.

### AFS Architecture and Whole-File Caching
1.  **Vice and Venus:** AFS nodes are divided into two categories. **Vice** machines are the dedicated file servers that store the definitive copies of all files. **Venus** is the client process running on user workstations that intercepts file system calls and communicates with Vice.
2.  **Whole-File Caching:** When a client program opens a file, Venus checks if it's in the local disk cache. If not, Venus fetches the *entire file* from the Vice server and stores it on the local disk.
3.  **Local Operations:** Once the file is cached locally, all subsequent `read` and `write` operations by the application are performed entirely on the local copy. This drastically reduces network traffic and server load.
4.  **Session Semantics:** Modifications to a file are only sent back to the Vice server when the client program closes the file (on `close()`).
5.  **Callbacks:** To maintain consistency, AFS uses a **callback promise** mechanism. When Vice sends a file to Venus, it also provides a callback promise, guaranteeing it will notify Venus if any other client modifies the file. If a file is modified, Vice breaks the callback on all other clients. The next time those clients open the file, Venus will know its cached copy is stale and must fetch the new version.

## Example
**AFS Callback Mechanism:**
1.  **Client A** opens `document.txt`. Vice sends the file and a callback promise to Venus A.
2.  **Client B** opens `document.txt`. Vice sends the file and a callback promise to Venus B.
3.  **Client A** writes to the file and calls `close()`. Venus A uploads the new version to Vice.
4.  Vice sends a message to Venus B: **"Callback broken on document.txt"**.
5.  Later, when **Client B** tries to `open()` the file again, Venus B sees the callback is broken, discards its local cache, and fetches the fresh copy from Vice.

## Applications & Use Cases
-   **University Campuses:** AFS was initially built to serve the entire CMU campus, allowing students to log into any computer and have fast, local-disk-speed access to their home directories via caching.
-   **Global Corporate Networks:** For companies with offices distributed globally, AFS provides a unified namespace `/afs/company.com/` allowing seamless file access with performance masked by aggressive whole-file caching.
-   **Software Development and Distribution:** Distributing large source trees where files are read frequently but written infrequently is an ideal workload for AFS.

## 3 Solved Numerical/Analytical Examples
**Example 1:**
Compare the network traffic generated by NFS vs AFS when a client opens a 10 MB file, reads it sequentially 5 times in a loop, and then closes it.
*Solution:*
-   **NFS:** Every `read` goes over the network (assuming standard block caching is quickly evicted or small). Total traffic ≈ 5 * 10 MB = 50 MB transferred over the network.
-   **AFS:** Upon `open()`, the whole 10 MB file is fetched. All 5 reads are served from the local disk cache. Total traffic = 10 MB over the network.

**Example 2:**
What happens in AFS if Client A and Client B simultaneously open the same file, modify it, and close it?
*Solution:*
AFS uses "last closer wins" semantics. If Client A closes the file first, the server updates its copy. When Client B closes the file shortly after, Client B's version overwrites Client A's version on the server. Client A's changes are lost.

**Example 3:**
Calculate the storage overhead required for a Venus client if it needs to cache 100 files, each with an average size of 2 MB.
*Solution:*
Since AFS uses whole-file caching, the local disk must have enough space to hold the entire contents of every cached file. Total storage required = 100 files * 2 MB/file = 200 MB on the local workstation disk.

## Previous Year Questions & Solutions
**[April 2018] Explain Andrew file system. (4 marks)**
*Solution:*
The Andrew File System (AFS) is a scalable distributed file system characterized by its use of whole-file caching and callbacks.
1.  **Architecture:** It separates the system into dedicated file servers called **Vice** and client processes called **Venus**.
2.  **Whole-File Caching:** When a user opens a file, Venus fetches the entire file from a Vice server to the client's local disk. All subsequent reads and writes happen locally without network interaction, resulting in high performance.
3.  **Upload on Close:** When the user closes the modified file, Venus uploads the updated file back to the Vice server.
4.  **Callbacks:** To ensure clients don't read stale data, Vice uses callbacks. When it delivers a file to a client, it guarantees to notify that client if the file is modified by someone else. If notified (a "callback break"), the client invalidates its cached copy.
