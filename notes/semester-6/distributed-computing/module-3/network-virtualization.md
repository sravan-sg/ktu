# Network Virtualization

## Explanation

Network Virtualization is the process of combining hardware and software network resources and network functionality into a single, software-based administrative entity (a virtual network). In the context of distributed systems, it refers heavily to the creation of **Overlay Networks**.

An overlay network is a logical, virtual network built on top of a physical underlying network (like the Internet). In an overlay, the nodes are application-layer processes, and the "links" between them are virtual links, which actually represent complex physical paths involving many physical routers.

Key Concepts:
- **Decoupling**: It decouples the logical topology required by the distributed application from the physical topology of the underlying network hardware.
- **Custom Routing**: Overlay networks can implement their own routing algorithms (e.g., routing based on content ID rather than IP address).
- **Encapsulation**: Data generated by the application in the overlay is encapsulated inside standard TCP/UDP packets and routed through the physical Internet.

## Example

Consider a Peer-to-Peer (P2P) file-sharing network like BitTorrent. 
- **Physical Network**: A graph of ISP routers, trans-oceanic cables, and home Wi-Fi routers.
- **Overlay Network (Virtual)**: A logical graph where Node A (in New York) has a direct "virtual link" to Node B (in Tokyo) because they are sharing the same file.

```text
[Overlay Network View]
Node A --------------------------- Node B
(Logical Link: 1 Hop)

[Physical Network Reality]
Node A -> Router1 -> Subnet -> OceanCable -> RouterX -> Node B
(Physical Links: 15 Hops)
```

## Applications & Use Cases

- **Virtual Private Networks (VPNs)**: Creating a secure, private logical network overlay on top of the public, insecure Internet using tunneling protocols (IPsec, OpenVPN).
- **Peer-to-Peer Networks**: Skype, BitTorrent, and Tor all build application-layer overlay networks to route traffic custom to their needs (e.g., anonymization or NAT traversal) rather than relying on standard IP routing.
- **Software-Defined Networking (SDN)**: In cloud environments (AWS, Azure), network virtualization allows multiple tenants to have their own isolated virtual IP subnets running on the exact same physical switches.

## 3 Solved Numerical/Analytical Examples

**Example 1: Overlay Routing Stretch Calculation**
"Stretch" in an overlay network is defined as the ratio of the latency in the overlay network to the shortest physical latency between two nodes. 
Node A wants to send a message to Node C in an overlay network, but must route it through Node B.
Physical Latencies: A to B = 20 ms. B to C = 15 ms. A to C directly = 25 ms.
Calculate the stretch.
*Solution:*
1. Overlay Latency (A -> B -> C) = 20 ms + 15 ms = 35 ms.
2. Shortest Physical Latency (A -> C) = 25 ms.
3. Stretch = Overlay Latency / Physical Latency = 35 / 25 = $1.4$.
*Meaning:* The virtual network routing is 40% slower than optimal physical routing.

**Example 2: Overlay Link Capacity vs Physical Bottleneck**
An overlay network defines a virtual link from Node A to Node C with a required bandwidth of 50 Mbps. The physical path goes through three links: L1 (100 Mbps), L2 (40 Mbps), L3 (1 Gbps). Can the virtual link be established?
*Solution:*
1. The capacity of a virtual link is bottlenecked by the physical link with the lowest bandwidth along its path.
2. Bottleneck = min(100, 40, 1000) = 40 Mbps.
3. Since the required capacity (50 Mbps) > bottleneck (40 Mbps), the virtual link cannot sustain the required bandwidth.

**Example 3: Scalability of Full-Mesh Virtual Topologies**
If an overlay network of 1,000 nodes attempts to maintain a full-mesh topology (every node maintains a virtual link/TCP socket with every other node), how many TCP connections must the network maintain, and how many must each individual node handle?
*Solution:*
1. Connections per node = $N - 1 = 1,000 - 1 = 999$ sockets.
2. Total connections in the network = $N(N-1)/2 = (1,000 \times 999) / 2 = 499,500$ TCP connections.
*Conclusion:* Full-mesh overlay topologies do not scale well due to state explosion, which is why real systems use structured topologies (like DHTs or trees) or supernodes.

**[April 2018] PART C - Q15a) Discuss Skype as a case study for network virtualization. (5 marks)**
*(Note: A full, dedicated answer to this question is provided in the `case-study-skype.md` file since Skype is the primary case study for network virtualization in the syllabus. Below is the summary specific to virtualization).*
*Solution:*
Skype acts as a prime example of network virtualization by building a massive Peer-to-Peer overlay network on top of the physical Internet. 
1. **Virtual Topology:** Instead of treating all internet nodes equally, Skype organizes nodes into a two-tier virtual topology consisting of "Supernodes" (high-bandwidth, public IP machines) and "Ordinary nodes" (endpoints behind NAT/firewalls).
2. **Decoupled Routing:** Skype does not rely on IP routing to find a user. It uses its overlay network's Global Index (hosted on Supernodes) to map a Skype Username to a current IP address.
3. **NAT Traversal (Tunneling):** If two ordinary nodes cannot communicate directly due to physical firewall restrictions, the virtual network routes their call data through a mutually accessible Supernode, acting as a virtual bridge, thus hiding the physical network's limitations from the end users.
